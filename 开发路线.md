# 开发计划（Roadmap）

---

# Phase 1 — 基础 DPDK 接收

目标：

实现：

```text
10G UDP RTP Receive
```

功能：

* hugepage
* DPDK init
* RX queue
* packet dump
* timestamp

输出：

```text
稳定 RTP 收包
```

macOS 适配：

* 当前 macOS 25.x / Apple Silicon 不提供 DPDK + NVDEC + DRM/KMS 的目标运行环境。
* 在 macOS 上以 POSIX UDP 接收器落地 Phase 1 的 RTP 收包能力，目标为 `xqc_rtp_annexb_receiver`。
* Linux/NVIDIA 生产路径仍保留 DPDK/GPUDirect/NVDEC 方向。

周期：

1~2 周。

---

# Phase 2 — RTP Reorder Engine

实现：

* sequence reorder
* jitter buffer
* packet loss
* FU-A
* STAP-A

输出：

```text
完整 AnnexB H264 stream
```

macOS 适配：

* `xqc_rtp_annexb_receiver` 支持 H.264 RTP single NAL、STAP-A、FU-A 重组并写出 Annex-B `.h264` 文件。
* 该目标用于本机协议验证和码流调试，不宣称 kernel-bypass 或 GPU zero-copy 延迟指标。

周期：

2~3 周。

# 工程原则

必须：

* move semantics
* no heap allocation in hot path
* lock-free queues
* cache aligned structures
* batch processing
* NUMA locality

禁止：

* shared_ptr hot path
* malloc in RX loop
* mutex in dataplane
* memcpy of frame buffers
